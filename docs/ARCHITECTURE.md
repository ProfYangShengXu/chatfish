## 2. 一次唤醒的完整数据流

```
群友发消息
   ↓
SnowLuma 推送 → bridge 收到
   ↓
进防抖批次（不是立刻唤醒）
   ↓
批次到期 → 触发判定
   ├─ 有人 @ 我 / 私聊我 / 拍我     → 直接进入回合
   ├─ 频率闭环允许 + 概率命中        → 进入回合
   └─ 否则                          → 只进摘要，不起回合
   ↓
装配 prompt（见第 3 节）
   ↓
投给 agent runtime
   ↓
agent 决定：
   ├─ 调发送工具  → bridge 发到 QQ
   ├─ 调 qq_mark_read → 本轮沉默（合法选项，不是失败）
   └─ 调唤醒配置工具 → 设定下次醒来的条件
   ↓
回合结束 → 会话结束检测 → 提炼事实 → 写入 memory/
```

## 3. Prompt 装配

这是整套框架里最影响成本的部分。装配顺序按「变化频率」排：

```
┌─ system（跨轮逐字节不变，缓存命中）────────────────────┐
│  安全规则 · 人格 · 行为准则 · 说话方式                  │
│  黑名单 · 示例 · 记忆使用规范 · 场地规则                │
└───────────────────────────────────────────────────────┘
┌─ 工具注册表（不变）───────────────────────────────────┐
└───────────────────────────────────────────────────────┘
┌─ 历史（只追加，不改写）───────────────────────────────┐
└───────────────────────────────────────────────────────┘
┌─ 本轮增量（唯一每轮变的部分）─────────────────────────┐
│  当前时间 · 此刻状态 · 未读消息 · 唤醒原因              │
│  进行中的话题 · 群友印象 · 参与度 · 别处近况            │
└───────────────────────────────────────────────────────┘
```

**铁律：一切可变内容只允许出现在最后。**

放错位置的代价是实打实的：把每轮都变的东西插进 system，
从那一个字节开始后面全部缓存失效 —— 在长对话里可能是十倍成本差。

配套要求：

- 工具注册表要定期审计，**删掉永远不会被调用的工具**。schema 是每轮都付的固定成本
- 跨轮不变的准则不要每轮重发。搬到 system 里，一份就够
- 人设写得再长也不该挤占工具预算 —— 工具用法留在角色卡按需读

## 4. 社交状态机

每个会话一份状态，三个相位：

```
      ┌──────────┐   触发      ┌──────────┐
      │  观望 idle │ ─────────→ │  活跃 active │
      └──────────┘            └──────────┘
           ↑                        │
           │      收尾/超时          │
           └────────────────────────┘
                    ↓
              ┌──────────┐
              │ 潜水 sleep │  ← 由 agent 自己设定醒来的条件
              └──────────┘
```

关键点：**「不发言」是一个正当结局，不是异常。**

如果 agent 只能「回」或「出错」，那它必然被逼着每条都回。
沉默权必须在机制层面给到，而不是在提示词里写一句「可以不说」。

## 5. 记忆分层

| 层 | 存储 | 注入方式 | 变化频率 |
|---|---|---|---|
| **常驻** | `AGENTS.md` | 每次会话开头整段注入 | 极低 |
| **情境** | 会话状态 JSON | 唤醒时拼进增量 | 每轮 |
| **长期** | PostgreSQL + pgvector | 按需检索 | 按查询 |

写入路径：**会话结束 → 提炼 → 去重 → 入库**，不是每条消息都记。

提炼的质量取决于喂进去的东西。一个常见的坑是把「唤醒提示词」当成「聊天记录」喂给提炼模型 ——
那样提炼出来的全是「不要当客服」这种提示词条款，跟用户没有半点关系。
**必须只提取真人说的话。**

---

## 6. 跨会话同步

私聊和群是两个独立会话，默认互相看不见。定时把各会话最近的消息摘要写进共享位置，
唤醒时把「另一边」那份带标签注入。

**标签必须写清楚** —— 不标来源，agent 会把群里的对话当成私聊内容回，或者反过来。
更严重的是私聊内容被当众说出来。

同步是**异步定时**的，不是实时的：隔几分钟的近况完全够用，人本来就是这样。

## 7. 缓存与成本

前缀缓存是本框架的命门。判据只有一条：**读 provider 返回的 usage 字段，不读自己的日志。**

- 请求级命中：第 2 个请求起每次 `cacheReadTokens > 0`
- token 级命中率：`cacheReadTokens / prompt_tokens`，agent 多轮里数学上永远 < 100%

单次命中率**掉下来**，就是有东西被插到了中间。这是铁律唯一能不看代码就验的形式。
